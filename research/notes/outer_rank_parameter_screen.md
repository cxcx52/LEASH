# Fixed-path outer-rank screening

Date: 2026-11-14. This is a pure arithmetic, communication, and heuristic cost
screen. It evaluates both outer commitment row ranks jointly in `4,...,16`,
with inner rank 24 and each previously verified seven-layer path fixed.
It does not execute a lattice algorithm or a prover and does not certify
concrete knowledge security.

## Result

Both paths have minimum passing common outer rank **9** in the specified
integer domain. Rank 8 falls below the old cube path's minimum in all five
cost models. Rank 9 preserves that minimum for the cube path and preserves
the stronger existing minimum for the energy-ball path.

| Fixed complete path | Outer rank 16 payload | Outer rank 9 payload | Saving |
|---|---:|---:|---:|
| Filtered cube, T=34, Gamma squared factor 21/2 | 185.734375 KiB | 161.234375 KiB | 24.5 KiB |
| Filtered energy ball E=104, T=30, Gamma squared factor 9 | 179.6484375 KiB | 155.1484375 KiB | 24.5 KiB |

The change saves exactly

    7 layers * 2 commitments * (16-9) rows * 64 coefficients * 32 bits
      = 200704 bits = 25088 bytes = 24.5 KiB.

The old rank-16 records remain unchanged. New records are
`notes/parameter-results/outer-ranks.json`, generated by
`scripts/outer_rank_parameter_screen.py`. They include every tested rank's
14 outer instances, the unchanged seven inner instances, all selected lattice
dimensions and block sizes, each of the five model outputs, and hashes of the
input paths and previous model records. `selected_parameters` explicitly
sets the new rank to 9; `fixed_parameters` preserves the original input
record. A fresh rank-specific CRS and target-relation manifest are required.

## Why changing the outer rank preserves the arithmetic path

The original paper, PDF page 15, explicitly gives the next full-ring equation
count as `K'=kappa+kappa_1+kappa_2+3`. Figure 3, page 18, Lines 15–20 gives the
same count: `kappa` inner commitment equations, three scalar ring equations,
and `kappa_1+kappa_2` outer commitment equations. Thus the count changes from
59 to 45 when the inner rank is 24 and both outer ranks change from 16 to 9.
The relation still has its separate norm constraint.

With `G=r(r+1)/2`, the packed witness length is

    W_next = 2n + r t1 kappa + (t1+t2)G.

It contains the decomposition digits of `z,t,g,h`, not the public commitment
outputs. Likewise the cap dimensions are

    D_z=nd,  D_u=d(r kappa+G),  D_g=dG.

Neither expression contains an outer row rank. In the first commitment the
number of ring columns is `r t1 kappa+G t2`; in the second it is `G t1`.
Only the numbers of rows and the public commitment output lengths change.

Consequently the fixed choices of decomposition bases, digit counts,
paired padding, `n`, `r`, honest `beta`, extracted target cap `B`, and final
witness encoding remain valid. Reconstruction and every commitment equation
must be instantiated with the newly sized matrices. Keeping the two outer
ranks equal also respects the repaired common output dimension of the first
commitment's t- and g-blocks.

Honest completeness depends on the fixed projection and folding bounds and
on uniform deterministic digit caps. Changing the number of aggregated
source equations does not change those caps. The first and second random
aggregation failure bounds depend on a nonzero residual and the number of
fresh aggregation trials, not the number of entries in that residual.
The JL, lifting, challenge-cardinality, and statistical budgets therefore
remain those of the respective fixed path.

The extraction invocation factors `1+r/(1-1/N)` and their product are also
unchanged. Local arithmetic costs and the initialization of reductions must
be recomputed for the new matrices; equal invocation counts do not assert
identical wall-clock runtime. The outer MSIS assumption instances change
because their row dimensions change. Their radius remains `2B`; the inner
collision instances and norms remain unchanged.

This is a new parameterized relation and setup. It does not authorize taking
an existing rank-16 transcript or CRS and merely dropping rows. All public
constraint arrays and independently sampled commitment matrices must match
the new dimensions. The algebraic dimension argument was independently
cross-checked by the R1CS reviewer; the numerical cost outputs below were
not included in that cross-check.

## Reproduction and model scope

The run used Sage 10.9 and a clean lattice-estimator checkout at commit
`53da5982597709ba0fdf94ea37a84d822310fd84`. The wrapper imports the existing
dimension optimizer and CRT candidate calculation and calls the pinned
`SISLattice.cost_euclidean` with exactly the same models as the earlier
screens. It verifies both saved arithmetic paths and checks their file hashes
against the prior pinned cost records. At rank 16 all finite old/new cost outputs
are asserted exactly equal. The selected parameters and payload are emitted
explicitly rather than inferred from a printed rounded table.

Run with Sage Python from the research root:

    sage -python scripts/outer_rank_parameter_screen.py --estimator "$ESTIMATOR" --output work/outer_rank_parameter_screen.json

The coefficient Euclidean norm is used throughout. The generic scalar SIS
dimension is the module dimension multiplied by `d=64`. The reported problem
is standard nonzero-integer SIS. Every radius remains below `q=4294967197`,
so the immediate integer vector `q e_j` lies outside these radius bounds.
The actual extraction collisions are nonzero modulo q; this distinction does
not turn the model into a separate certified nonzero-residue hardness result.

The three CoreSVP exponents omit polynomial factors. MATZOV classical and
its estimator quantum depth-width variant have different cost conventions;
the latter is not a direct quantum security theorem from the MATZOV paper.
The selected rank-9 generic blocks 643–874 all lie within the estimator's
documented fit range through block 1024. Several old rank-16 outer estimates
were extrapolations beyond that range. Being inside the fit interval does
not make the GSA or cost model a rigorous lower bound.

The payload remains the fixed-width ordinary-core prover payload. It includes
both outer commitments in every layer, six aggregation polynomials per layer,
1024 JL coordinates, and the final decomposed witness. It excludes source
commitments, public instances/CRS, verifier challenges, framing, Fiat–Shamir
material, and rejected complete attempts. The new cube ledger is
`491520+829312=1320832` bits; the new energy-ball ledger is
`490496+780480=1270976` bits.

Neither these communication numbers nor the model thresholds absorb the
computational extraction losses. The reviewed cubic-root refinement improves
those algebraic losses but still needs advantages at the complete reduction
runtime, including nested invocations, initialized rejection histories, and
any chosen truncation loss. No numerical 128-bit knowledge-security claim
follows from this screen.

No shared driver, old parameter record, public package, prover, or git commit
was modified. Only the new wrapper, output, and this report were added.
