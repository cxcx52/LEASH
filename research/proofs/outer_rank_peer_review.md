# Review of the fixed-path outer-rank change

Date: 2026-11-14. This separate development pass checks the dimension argument and the cost-screen implementation; it is not a new security proof or an independently repeated Sage run.

The target witness contains reconstructed z digits and t/g/h digits. The outer commitment outputs are public, so reducing their row ranks does not remove witness digits. For fixed inner rank and digit parameters, the first and second outer column counts remain `r*t1*kappa+G*t2` and `G*t1`. Only their row counts change. The target ring-equation count changes from `kappa+3+32` to `kappa+3+18`, namely 59 to 45 at inner rank 24. This agrees with the original target specification already checked by the R1CS reviewer.

The norm caps, paired-padding lengths, honest witnesses, challenge distributions and statistical root-count bounds do not depend on the outer row count. Each new target and each commitment matrix must nevertheless be instantiated at the new dimensions; taking an existing transcript and deleting rows is not justified. The report states this requirement. The source frontend is not included in this ordinary-core rank change.

The wrapper validates the complete fixed paths, prior pinned-model inputs and raw input hashes. It screens both outer roles at every level for every common rank 4 through 16. It keeps the old seven inner instances, compares unrounded model-specific minima, and verifies the rank-16 outputs against the previous records. Its threshold is explicitly the old cube minimum; the reported rank-nine outer minima also exceed the stronger energy-path inner minima. The 200704-bit saving follows directly from the changed public commitment lengths and agrees with the final ledgers.

The selected rank-nine generic blocks are within the fitted cost model's stated range, while the model still assumes GSA behavior on structured module kernels. A minimum cost estimate is not an advantage upper bound at the complete extraction time. The new cubic-root proof, restart initializers and norm conventions must still be accounted for in any concrete security statement. The review found no blocker to the reported fixed-path arithmetic and model-screen comparison, with these limits.
